The problem

Your help desk is an
authentication bypass.

Account-takeover defenses assume the attack comes through a login screen. Vishing (voice phishing) walks in through the phone line instead.

“Hi, this is Jordan from Accounting. I got a new phone and I'm locked out. Can you reset my MFA real quick? I've got a call with the CFO in five minutes.” — An attacker who read Jordan's LinkedIn

How it works

Enroll once. Verify every call.

Built on TOTP (RFC 6238), the same standard as login MFA, so “read me the code” is an ask every employee already understands.

Once
00 · ENROLL

Email a QR code

The agent clicks Email QR Code. Vixxing generates a fresh secret and emails a QR code. The employee scans it into any authenticator app.

On every call
01 · ASK

“Read me the code.”

From the authenticator on their enrolled phone. It takes a few seconds.

02 · VERIFY

Type it, click Verify

The server checks it against the stored secret, allowing one 30-second step of drift either way.

03 · DECIDE

Proceed, or don't

Caller Verified or Invalid code. Do not proceed. No judgment call.

The agent dashboard

Built for someone with a caller on hold.

Find the caller, read the code, verify. Everything else an IT team needs to manage enrollment sits one click away.

Regenerate QR

New phone or suspected compromise? Issue a new secret and re-email it. The old device stops working.

Bulk import & actions

Add employees one at a time or from a CSV. Enroll, unenroll, or delete many at once.

CSV export, no secrets

Export names, emails and enrollment status for audits. TOTP secrets are never included.

Graph, with SMTP fallback

Sends through Microsoft Graph by default and falls back to SMTP automatically. The dashboard says which one delivered.

Staff-only by default

Every view requires a Django staff login. No self-service portal for an attacker to poke at.

Security posture

Honest about where it belongs.

Vixxing is an internal tool for a trusted network. It's deliberately small, and it tells you plainly what it does and doesn't protect.

The recommended stack: a Windows Server VM running it under NSSM behind Caddy for TLS, with Exchange mail-flow rules encrypting enrollment email.

  • ✓
    Your data stays on your serverSelf-hosted. No SaaS, no telemetry, no third party holding your employees' secrets.
  • ✓
    No credentials in the repoGraph and SMTP credentials live in your own .env. Cloning grants nobody access to anything.
  • ✓
    Open source, GPLv3Read every line that handles your secrets. Tested in CI on Python 3.12 and 3.13.
  • !
    LAN-only by designNot hardened for the public internet. Put it behind TLS and a VPN or internal proxy before it leaves a trusted segment.
  • !
    Secrets are stored unencryptedProtect the database and host accordingly, and encrypt enrollment email where you can.

Quick start

Running in five minutes.

Python 3.12+ and a way to send email. That's the whole list.

bash 
$ git clone https://github.com/miles-howell/vixxing.git
$ cd vixxing
$ python -m venv .venv && source .venv/bin/activate
$ pip install -r requirements.txt

$ cd TOTP
$ cp .env.example .env        # add your secrets
$ python manage.py migrate
$ python manage.py createsuperuser
$ python manage.py runserver 0.0.0.0:8000

Bring your own mail

Register an Entra app with Mail.Send for Microsoft Graph, or just set EMAIL_HOST for SMTP. Either works.

Make it yours

Change the issuer name, sender address and email templates to match your org before sending real enrollment mail.

Go beyond the dev server

Run under Gunicorn behind an internal reverse proxy for anything longer-lived than a test.
